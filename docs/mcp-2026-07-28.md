# MCP 2026-07-28 —— 实现要点速查（从官方规范摘录，实现以本文为准）

来源：<https://modelcontextprotocol.io/specification/2026-07-28/>（changelog / basic / versioning / transports/streamable-http / server/tools）

## 与旧版的关键差异（2021 → 2026-07-28）

| 变化 | 影响 |
| --- | --- |
| 去掉 `initialize` / `notifications/initialized` 握手，**协议无状态** | 每个请求自带 `_meta` 元数据；不存 session |
| 去掉 `Mcp-Session-Id` | 不签发、不回显；收到也忽略 |
| 去掉 GET 端点、`Last-Event-ID`、SSE 断点续传 | GET / DELETE → **405 Method Not Allowed** |
| 新增 `server/discover`（**必须实现**） | 返回支持版本、capabilities、serverInfo |
| 新增 `subscriptions/listen`（取代 GET 流 + `resources/subscribe`） | 长连接 SSE，只送客户端点选的变更通知 |
| 所有 result **必须**带 `resultType` | `"complete"` / `"input_required"` |
| `tools/list` 等列表结果 **必须**带 `ttlMs` + `cacheScope` | `cacheScope`: `"public"` \| `"private"` |
| 新增请求头 `Mcp-Method`、`Mcp-Name` | 必须与 body 一致，否则 `-32020` + 400 |
| 错误码重新分区 | `-32020` HeaderMismatch、`-32021` MissingRequiredClientCapability、`-32022` UnsupportedProtocolVersion；`-32002` 废弃（资源不存在改 `-32602`） |
| `ping`、`logging/setLevel`、`notifications/roots/list_changed` 移除 | 日志级别改为 per-request `_meta["io.modelcontextprotocol/logLevel"]` |

## 请求 `_meta`（body 里，必填）

```jsonc
"params": {
  "_meta": {
    "io.modelcontextprotocol/protocolVersion": "2026-07-28",   // 必填
    "io.modelcontextprotocol/clientCapabilities": {},          // 必填（可空对象）
    "io.modelcontextprotocol/clientInfo": { "name": "x", "version": "1" }, // 可选
    "io.modelcontextprotocol/logLevel": "info"                 // 可选
  }
}
```

- 缺必填字段 → JSON-RPC `-32602`，HTTP **400**。
- 需要客户端未声明的 capability → `-32021`（`data.requiredCapabilities`），HTTP **400**。
- 服务端 **SHOULD** 在每个 result 的 `_meta` 里带 `io.modelcontextprotocol/serverInfo`。

## HTTP 传输（Streamable HTTP）

- 单一 endpoint，**只接受 POST**（每请求一个 JSON-RPC 消息）。
- `Accept` 需同时含 `application/json` 与 `text/event-stream`（客户端义务；服务端按需选其一返回）。
- 请求头：`MCP-Protocol-Version`（必须等于 body 里的版本）、`Mcp-Method`（= `method`）、`Mcp-Name`（= `params.name` / `params.uri`，用于 `tools/call`、`resources/read`、`prompts/get`）。
- 头/体不一致或缺头 → HTTP 400 + `-32020 HeaderMismatch`。
- 版本不支持 → HTTP 400 + `-32022`，`data: {supported: [...], requested: "..."}`。
- 方法不存在 → HTTP **404** + `-32601 Method not found`。
- 通知（无 `id`）→ **202 Accepted**，无 body。
- SSE 场景：`Content-Type: text/event-stream`，`X-Accel-Buffering: no`，可发 `notifications/progress`、`notifications/message`（仅请求相关）；**不得**在流上发 JSON-RPC 请求（服务端→客户端交互走 MRTR）。
- `Origin` 头存在且非法 → **403**。本地部署建议只绑 127.0.0.1。
- `Mcp-Name` 非 ASCII/不可安全表示时用 Base64 哨兵：`=?base64?{b64}?=`；服务端比较前必须解码。

## 方法清单（本实现）

| 方法 | 说明 |
| --- | --- |
| `server/discover` | `{ resultType, supportedVersions|protocolVersions, capabilities, serverInfo }` |
| `tools/list` | `{ resultType, tools[], ttlMs, cacheScope }`，顺序稳定 |
| `tools/call` | `{ resultType, content[], structuredContent?, isError? }` |
| `resources/list` / `resources/read` | 实例句柄作为资源暴露；`ttlMs`/`cacheScope` 必需 |
| `subscriptions/listen` | SSE 流，先 `notifications/subscriptions/acknowledged`（带 `_meta["io.modelcontextprotocol/subscriptionId"]`），再推 `notifications/tools/list_changed`，空闲发 `:` keep-alive 注释行 |

工具执行错误（模型可自纠）→ `result.isError = true` + 文本；协议错误（未知工具、参数结构错）→ JSON-RPC error `-32602`。

## stateful 工具设计（规范 §Stateful Tools）

协议无会话，跨调用状态**必须**用服务端签发的显式句柄在工具参数里传递 —— 与本书源库的 TTL 实例注册表天然对应：`booksource_create` 返回 `source_id`，其余工具用它做参数；句柄有 TTL、过期后调用返回可自纠的 `isError`。
